Презентация проекта

Медицинский портал mp-v2

Запись к врачу, документы и история приёмов. Микросервисная платформа с ролевым доступом, событийной архитектурой и полным циклом наблюдаемости.

Next.js + TypeScript NestJS-сервисы Keycloak (OIDC) PostgreSQL RabbitMQ Docker Compose

Три роли — три кабинета

  • Пациент (USER) — запись на приём за 4 шага, история, документы, профиль
  • Врач (DOCTOR) — приёмы, расписание, пациенты и их документы, результаты приёмов
  • Администратор (ADMIN) — врачи, специализации, управление и перенос записей
Как устроено

Архитектура и стек

Монорепо pnpm: web-фронтенд, gateway, сервисы домена, инфраструктура в Docker.

Клиент и периметр

  • apps/web — Next.js (App Router), SSR-страницы, BFF-прокси /api/bff
  • Токены только в HttpOnly-куках — не в localStorage и не в DOM
  • gateway:4000 — единая точка: CORS, JWT (JWKS), роли, rate limit, маршрутизация

Сервисы

  • identity — профиль, регистрация, аватар
  • catalog — врачи, специализации, расписания, слоты
  • appointment — записи, перенос, история, события
  • document — загрузка/выдача документов (проверка по магическим байтам)
  • notification — письма, outbox → RabbitMQ → DLQ

Данные и асинхронность

  • PostgreSQL — схема на сервис, транзакции и конкуренция за слот
  • RabbitMQ — события домена, consumer-группы, dead-letter
  • Outbox — гарантированная доставка событий из транзакции

Наблюдаемость и качество

  • Структурные логи + requestId на сквозной трассировке
  • Prometheus: метрики сервисов и алерты outbox/consumers
  • Mailpit — приём почты на стенде
  • Vitest: unit + integration, e2e-сценарии этапов

Ключевые решения

  • SSR-запросы идут на gateway напрямую с токеном сессии
  • 401 «Токен просрочен» → тихий refresh; невозможно → редирект на вход
  • Контракты типизированы (@mp/contracts) — web и сервисы из одного источника

Первый экран

Лендинг и авторизация

Публичная страница и вход через Keycloak; после входа — редирект в кабинет своей роли.

Лендинг: публичная страница с описанием и входом
Профиль пациента после входа: аватар 150×150 и данные

Что важно

  • Разделы портала открываются после входа и зависят от роли
  • Вход/выход — OIDC-флоу Keycloak, сессия в HttpOnly-куке Auth.js
  • После логина — редирект в кабинет (пациент → профиль, врач → приёмы, админ → врачи)
  • Админ без аватара — инициалы (решение по продукту)
  • Недоступные роли скрыты в меню, прямые URL отдают 403-состояние

Надёжность входа

  • После простоя access-токен истекает → тихий refresh без ошибок
  • Обновить невозможно → редирект на страницу авторизации с callbackUrl

Администрирование

Диалог переноса записи

Недельная лента слотов выбранного врача: день = колонка, свободные — зелёные.

Как работает

  • Врач выбирается из той же специализации — чужие не подставляются
  • Навигация по неделям (‹ Неделя / Неделя ›), текущая неделя закрыта назад
  • «Превью: слот не выбран» → выбор слота показывает итог
  • Причина переноса (от 3 символов) — попадает в журнал

Проверки

  • Занятые/прошедшие слоты недоступны
  • Повторный перенос в чужой слот отклоняется сервером
Событийная доставка

События, письма и надёжность

Outbox → RabbitMQ → notification → письмо. Отказы не теряются: DLQ и алерты.

Mailpit на стенде: письма «Запись отправлена/подтверждена»

Цепочка

  • Запись создаёт событие в outbox в одной транзакции
  • Relay публикует в RabbitMQ
  • notification шлёт письмо (Mailpit на стенде)
  • Ошибки → повторы → dead-letter

Письма в системе

  • Запись отправлена на подтверждение
  • Запись подтверждена / отклонена / перенесена
Эксплуатация

Метрики и алерты

Prometheus: алерты на рост очередей, ошибки consumer-ов и lag outbox.

/alerts: DlqGrowing, ConsumerErrors, QueueBacklog, OutboxLagHigh, OutboxPublishFailures

Мониторинг

  • Метрики всех сервисов + gateway
  • Правила алертов по outbox и consumers
  • Сейчас: все правила inactive — система здорова

Диагностика

  • Сквозной requestId в логах и ошибках API
  • Структурные логи, единый формат ошибок ApiError
  • RabbitMQ management: очереди, DLQ, консьюмеры
