## 1. Методика

|--------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

| Критический путь   | Цепочка зависимостей внутри этапа (длительность задач `L`/`M` подряд); этапы идут последовательно — между ними ворота Эпика R                                                            |
| Ревизия            | **09.11.2026 (итерация 2)** — полная переоценка всех этапов + задача 2.7; итерация 1 — решения по несостыковкам этапов 2.1–5. Детали — [§2.1](#21-полная-переоценка-по-задачам-09112026) |

Календарный срок этапа = **максимум** из двух величин:

1. `Σ человеко-дней этапа ÷ 25` — при идеальном параллелизме;
2. `критический путь этапа` — при последовательном проходе цепочки зависимостей.

Далее сроки этапов суммируются (ворота между этапами) и округляются вверх.

## 4. Оценка при работе с нейросетью

### 4.1 Что уже готово для ИИ-разработки

Эффективность модели определяется качеством входного контекста — в проекте он собран:

- [prompts-stage1.md](prompts-stage1.md) — готовые промпты на задачи Этапа 1 (P0-контекст + 20 промптов);
- [functional-spec.md](functional-spec.md) — у каждой задачи чек-лист и **проверяемые AC** (главный инструмент валидации
  генерации);
- [design/*.md](design/README.md) — ASCII-макеты с компонентами MUI и состояниями (вход для фронтенд-генерации);
- [fsd.md](fsd.md) — жёсткие границы слоёв + ESLint-линт (механический отсев нарушений генерации);
- `packages/contracts` + `tsc --noEmit` + CI quality gate — контракты и типы ловят галлюцинации API.

### 4.2 Выигрыш по типам задач

Коэффициент — доля трудозатрат, **остающихся** после применения нейросети (1.0 = без выигрыша).

| Тип задач                               | Примеры                            | Коэффициент   | Почему именно столько                                                 |
|-----------------------------------------|------------------------------------|---------------|-----------------------------------------------------------------------|
| Boilerplate, каркасы, CRUD, шаблоны     | 0.7, 0.8, 3.1, 3.3, 4.1            | **0.35–0.5**  | Генерация по спеке + контракту; проверка — линт/типы                  |
| UI по макетам (MUI, состояния, адаптив) | 2.1, 2.2, 2.4, 2.5, 5.5, 9.2-форма | **0.4–0.5**   | Макет + тема на входе, результат детерминирован                       |
| Auth, гарды, BFF                        | 1.1, 1.2, 1.3, 2.6                 | **0.5–0.6**   | Генерируется легко, но требует ручной security-проверки               |

### 4.3 Сколько стоит «работать с нейросетью»

Чистое время генерации — не тот показатель, который нужно планировать. К оценке добавляется:

| Статья                                                            | Надбавка                        |
|-------------------------------------------------------------------|---------------------------------|
| Формулирование контекста (спека + макет + контракт + AC в промпт) | +10–15 % к времени задачи       |
| Ревью сгенерированного кода, отсев лишнего и «умных» абстракций   | +10–15 %                        |
| Правка галлюцинаций (несуществующие API/пути/типы)                | +5–10 %                         |
| **Итого буфер проверки**                                          | **×1.3** (заложен в сценарий C) |

Поэтому сценарий C = `задачи × коэффициент §4.2 × 1.3` + `аудиты × 0.7` + `пост-MVP × 0.6 × 1.3`.

**Что нейросеть не ускоряет** (оставляем плановые сроки): интеграционные прогоны в compose, отладку в окружении,
нагрузочные тесты, бэкапы и восстановление, согласования и ворота Эпика R.

## 7. Допущения

1. Оценки спеки (`S/M/L`) — человеко-дни разработчика, без времени на обучение стеку (NestJS/Prisma/Keycloak команда
   осваивает в Этапе 0–1, это входит в буфер B).
2. Загрузка 100 % в расчётах A/B/C; отпуска, болезни, встречи не моделируются — покрываются буфером B (×1.5) и
   коэффициентом координации ×1.1.
3. Этапы идут последовательно (ворота Эпика R), внутри этапа — максимальный параллелизм.
4. Аудит Эпика R оценён как `M×4 + S×2 = 14` чел-дней на проход и выполняется после **каждого** этапа 0–5; подэтап 2.1 —
   сокращённый проход R.1/R.5/R.6 = 3 чел-дня (полный — на Этапе 3).
5. Сценарий C предполагает, что промпты есть (сейчас — только на Этап 1) и что генерация идёт под AC задачи, а не «в
   пустоту».
6. Стоимость инструментов ИИ (подписки) в трудозатраты не входит — считается отдельно как операционные расходы.

   несостыковкам этапов 2.1–5. Шкала расширена вариантом `L+` = 6–7 дней
