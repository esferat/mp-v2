## Блоки и компоненты

| Блок                 | Компонент MUI                                                                                                          | Данные / логика                                                                                                                                                         |
|----------------------|------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Хлебные крошки/назад | `Breadcrumbs`/`IconButton` + `Typography h5`                                                                           | Имя врача — из `get-doctor`                                                                                                                                             |
| Основная информация  | `TextField` ×3 (ФИО), `Autocomplete` (специализации), `Select` (статус)                                                                                              | `features/create-doctor` / `update-doctor`; Zod-схема контракта                                                                                                         |
| Учётная запись       | `TextField` ×2 (email, пароль) — отдельный блок; в edit с учёткой — только email                                          | сага `identity` (`registerDoctor` / `createDoctorAccount`): **учётную запись создаёт админ всегда** (9.1); формат/уникальность email → `409` — [10.2](../functional-spec.md#102-email-врача-и-приглашение-по-ссылке--m) |
| Валидация расписания | валидация в `entities/schedule` → поля + `Alert`                                                                       | период кратен длительности; start < end; 5–240 мин; ≥ 1 день → **400** на конкретное поле, не 500                                                                       |
| Рабочие дни          | `FormControlLabel` + `Checkbox` ×7                                                                                     | `FormArray`-аналог в react-hook-form                                                                                                                                    |
| Превью слотов        | вычисляемый `Typography body2`                                                                                         | Живой пересчёт при изменении периода/длительности (KISS: на клиенте, подтверждение — сервер)                                                                            |
| Слоты                | `Chip`-сетка (занятые — `disabled`)                                                                                    | `GET /api/scheduling/slots?doctorId&…` — только после сохранения                                                                                                        |
| Фото                 | `shared/ui/image-cropper` (react-easy-crop)                                                                            | → `file-service` → `features/upload-doctor-photo` ([3.4](../functional-spec.md#34-фото-врача-через-file-service--m)); ошибка типа/размера — `Alert`                     |
| Сохранение           | `Button variant="contained"`                                                                                           | Двойной клик заблокирован; успех → редирект в список + тост; 409/400 — к полям                                                                                          |

## Состояния

| Состояние               | Поведение                                                                                                                                                                   |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| loading                 | Скелетон формы                                                                                                                                                              |
| 404 (id нет)            | Страница «Врач не найден» + кнопка «К списку»                                                                                                                               |
| несохранённые изменения | При уходе — `Dialog` «Есть несохранённые изменения» (Уйти/Остаться)                                                                                                         |
| архивирование           | `Dialog`: «Врач исчезнет из записи, история сохранится» → `status=INACTIVE`                                                                                                 |
| email занят (409)       | Ошибка на поле «Email уже зарегистрирован» / «Email уже привязан к другому врачу»; учётная запись и карточка не созданы (identity идёт до catalog)                      |
| приглашение отправлено  | Тост после сохранения: «Приглашение отправлено на *{email}* — ссылка активации действует 12 ч»; повтор — кнопка «Отправить ещё раз» (скрыта после активации учётной записи) |

## Правки

- Создание и редактирование — одна форма (разница: `id`, наличие слотов/фото).
- `PUT` обновляет строго по `:id` (сверка с телом — 400 при расхождении).
- **Правило: учётную запись создаёт администратор всегда** — при создании врача email и пароль обязательны
  (сага `registerDoctor`, 9.1). У существующего врача без учётной записи открывается блок «Создать учётную
  запись» (email + пароль) → `POST /api/identity/doctors/:doctorId/account`: привязка идёт ДО сохранения
  карточки (занятый email → 409 падает раньше частичных сохранений), при сбое — компенсация, повтор идемпотентен.
- Приглашение по ссылке (`executeActionsEmail`) отложено в
  [10.2](../functional-spec.md#102-email-врача-и-приглашение-по-ссылке--m): сейчас «простой кейс» —
  пароль задаётся при создании.
