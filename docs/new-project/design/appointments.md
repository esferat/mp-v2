## Блоки и компоненты

| Блок | Компонент MUI | Данные / логика |
|---|---|---|
| Фильтры | `DatePicker` ×2 (период), `Select` ×3 | В URL-параметрах (F5 восстанавливает); данные — `features/get-appointments` |
| Таблица | `shared/ui/table` | `widgets/appointments-table`, серверная пагинация по 10 |
| Пациент/врач | `Typography` + `Tooltip` (полное ФИО) | denormalized поля записи (не ходим в справочники) |
| Время приёма | `Typography mono` | `localDate + start/end` из `timeSlot` |
| Статус | `Chip` color по статусу | `entities/appointment` (статусная машина) |
| Действия | `Button size=small` «✓ Принять» / «✗ Отклонить» | Только для `SUBMITTED`; → `set-appointment-status` → outbox `appointment.approved/declined.v1` |
| Отмена | `Menu` «⋯» → «Отменить запись» | `Dialog`-подтверждение с причиной (опционально) |

## Состояния

| Состояние | Поведение |
|---|---|
| loading | Скелетон строк |
| empty (нет записей за период) | «Записей за период нет» + «Сбросить фильтры» |
| error | Тост + «Повторить» |
| действие | Кнопка → loading на строке; успех — обновлённый `Chip`; 409 (уже не `SUBMITTED`) — тост «Запись уже обработана» + тихая перезагрузка строки |
| realtime | Новое событие `appointment.*` в другом вкладке — инвалидация списка |

## Логика
- Смена статуса идемпотентна (повторный approve → 200 с тем же состоянием или 409, без побочных эффектов).
- Причина отказа отображается в тултипе/строке (для USER — в [истории](history.md)).
