# Страница: Регистрация

**Маршрут:** `/auth/register` → **форма регистрации Keycloak** (тема `mp-portal`, [2.7](../functional-spec.md#27-переделка-ui-для-keycloak-тема-и-письма--l)) · **Задачи:** 1.4, 2.7 · **Роль:** гость

> **Канон от 09.11.2026:** регистрация — страница темы Keycloak (email, пароль, имя/фамилия); карточка пациента (ФИО, дата рождения) и файлы (аватар/документ) **добираются в профиле** ([profile.md](profile.md)). Макет ниже описывает поток «регистрация → добор данных»; поля «Фамилия/Имя/Отчество/Дата рождения» и Шаг 2 относятся к профилю, а не к форме Keycloak.

Двухшаговый мастер. Шаг 2 (аватар/документ) — в профиле, относится к Этапу 2; на Этапе 1 доступен как пропускаемый («Пропустить»).

## Блоки и компоненты

| Блок | Компонент MUI | Данные / логика |
|---|---|---|
| Мастер | `Stepper` (nonLinear=false) | 2 шага; обратный переход сохраняет введённое (state в `processes/registration`) |
| Поля | `TextField`, `DatePicker` | В форме Keycloak — email/пароль/имя/фамилия; отчество и дата рождения — в профиле (см. примечание выше). Пароль: ≥ 8, наличие цифры (подсказка `helperText`) |
| Отправка | `Button` | Регистрация — форма Keycloak (тема `mp-portal`, [2.7](../functional-spec.md#27-переделка-ui-для-keycloak-тема-и-письма--l)); после входа → `/cabinet/profile` (добор карточки — [1.4](../functional-spec.md#14-сага-регистрации--l)) |
| Ошибки | `Alert` + `FormHelperText` | `EMAIL_EXISTS` → подсветка email «Пользователь уже зарегистрирован» + ссылка «Войти»; 5xx → «Не удалось завершить регистрацию, попробуйте ещё раз» с `requestId` |

## Состояния

| Состояние | Поведение |
|---|---|
| loading (шаг 1→2) | Кнопка disabled; на сервер — без задержек |
| loading (завершение) | Полноэкранной нет: карточка с прогрессом «Создаём аккаунт…» |
| ошибка саги (откат) | Тост «Регистрация не завершена, данные не потеряны — повторите», форма заполненной |
| успех | Редирект `/cabinet/profile` + тост «Добро пожаловать!» |

## Валидация
- Дата рождения ≤ сегодня, не раньше 1900.
- Пароли совпадают (проверка на клиенте и повторно на сервере).
- Дубль по email → идемпотентный повтор саги не создаёт второй аккаунт.
