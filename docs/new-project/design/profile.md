# Страница: Личный профиль (все роли)

**Маршруты:** `/patient/profile` (USER) · `/admin/profile` (ADMIN) · `/doctor/profile` (DOCTOR) · **Роль:** любая ·
**Задачи:** **10.1** (данные пациента — 4.2)

Единая страница: общий слайс `features/edit-profile` + виджет `widgets/profile-form`, три маршрута — три тонкие обёртки
(вариант 1А в [10.1](../functional-spec.md#101-личный-профиль-для-учётки-любой-роли--l)). Пункт меню «Профиль» в шапке
(`layout.md`) ведёт на маршрут своей роли.

## Разница по ролям

| Роль / маршрут               | Источник данных                                            | Поля формы                                      | Только чтение                                                             |
|------------------------------|------------------------------------------------------------|-------------------------------------------------|---------------------------------------------------------------------------|
| `USER` → `/patient/profile`  | `patient-service` (`GET/PUT /api/patient/:id`, задача 4.2) | ФИО, дата рождения, email, фото, скан документа | дата регистрации                                                          |
| `ADMIN` → `/admin/profile`   | `identity` (`GET/PATCH /api/identity/me`)                  | ФИО, email                                      | роль (её меняет только админ, 1.6)                                        |
| `DOCTOR` → `/doctor/profile` | `identity` (email) + `catalog` (ФИО)                       | email                                           | ФИО, специализация, статус — правит админ в [doctor-form](doctor-form.md) |

Фото и скан документов у `ADMIN`/`DOCTOR` не отображаются; пароль не редактируется в форме — только «Сменить пароль».

## Блоки и компоненты

| Блок            | Компонент MUI                                                 | Данные / логика                                                                                              |
|-----------------|---------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| Назад/заголовок | `IconButton` + `Typography h5`                                | Заголовок — «Профиль», подзаголовок — ФИО из сессии/карточки                                                 |
| Фото (USER)     | `shared/ui/image-cropper` + `Avatar`                          | `features/upload-patient-photo` → `file-service` (4.3); скан документа — виджет из карточки (4.4/4.5)        |
| Личные данные   | `TextField` ×5 + `DatePicker`                                 | `widgets/profile-form`, Zod-валидация; источник — таблица по ролям выше                                      |
| Учётная запись  | `Typography body2` (роль, статус) + `Button` «Сменить пароль» | Роль из сессии; пароль → flow Keycloak ([1.5](../functional-spec.md#15-восстановление-пароля--m), после MVP) |
| Сохранение      | `Button variant="contained"`                                  | `features/edit-profile` → `PATCH` своего профиля; двойной клик заблокирован; успех — тост «Сохранено»        |
| Email           | `TextField type="email"` + подсказка                          | Смена через `identity` → Keycloak Admin API; в события не попадает (PII)                                     |

## Состояния

| Состояние                | Поведение                                                                                 |
|--------------------------|-------------------------------------------------------------------------------------------|
| loading                  | Скелетон формы (6 строк)                                                                  |
| email занят (409)        | Ошибка на поле «Email: уже используется» + ссылка «Войти этим email»                      |
| чужой профиль / нет роли | [403](README.md#403--404) — страница без формы                                            |
| сессия истекла           | Редирект `/auth/login?callbackUrl=…` + тост                                               |
| ошибка сети (5xx)        | Тост + `requestId` + «Повторить»; введённое не теряется                                   |
| изменение ФИО (USER)     | После сохранения — инвалидация списков `scheduling` (< 5 с, событие `patient.updated.v1`) |

## Валидация

- email — формат + уникальность (сервер → `409`); дата рождения ≤ сегодня, не раньше 1900 (USER); обязательные ФИО
  (USER/ADMIN).
- Правка только своих данных: `sub` из токена ↔ сущность; иначе — `403` (AC 10.1).
- Сохранение — `optimistic`-обновление с откатом при ошибке (как в 4.2).
