# Медицинский портал v2 — проектирование с нуля

> **Принятое решение:** вариант архитектуры **C — «полные микросервисы с событийной моделью»** (см. [architecture.md](architecture.md)). Бэкенд-сервисы — на **NestJS + TypeScript**. Все внутренние проекты обязаны следовать **Feature-Sliced Design** (см. [fsd.md](fsd.md)).

Документы по постановке задач и архитектуре нового проекта. Домен перенесён из существующей системы (см. [общую документацию v1](../../../docs/README.md)), стек полностью новый. Каталог — `mp-v2/docs/new-project/`: документация лежит внутри git-репозитория рядом с кодом.

## Стек

| Слой | Технология |
|---|---|
| Frontend | **React** + **Next.js** (App Router, **SSR** обязателен), **TypeScript** (strict), Feature-Sliced Design; **BFF** в `web` — браузер ходит только в `/api/bff/*` |
| Дизайн-система | **Material UI (MUI)** — тема (`createTheme`), токены, готовые компоненты; обёртки живут в `shared/ui`, прямой импорт `@mui/*` запрещён линтом |
| Backend-сервисы | **NestJS** + **TypeScript** (strict) + **Prisma**, Feature-Sliced Design; внутренняя архитектура — **MVC + Hexagonal** (порт в `entities`, адаптер в `shared/api`, ядро без инфраструктуры) |
| Коммуникация | Синхронный REST (внутренний) + асинхронные события через **RabbitMQ** (topic exchange, outbox, DLQ) |
| API-слой | **api-gateway** (NestJS): авторизация, rate-limit, агрегация, трассировка |
| Данные | **PostgreSQL** — база на сервис, миграции через **Prisma** |
| Хранилище файлов | **MinIO** (S3-совместимый форк), presigned URL |
| Идентичность | **Keycloak**: реалм, роли `ADMIN`/`USER`/`DOCTOR`, OIDC для web, client-credentials для сервисов |
| Качество кода | **ESLint** (вкл. правила границ FSD) + **Prettier** + **tsc strict** |
| Принципы кода | **SOLID, KISS, DRY** — [конвенции](fsd.md#7-принципы-кода-solid-kiss-dry), чек-лист ревью, quality gate и этапный аудит после каждого этапа |
| Логи и наблюдаемость | Структурированные логи **pino** → **Filebeat** → **Elasticsearch** → **Kibana** (поиск по `traceId`, дашборды, алерты) |
| Контейнеризация | **Docker** / Docker Compose |
| Инфраструктура | **nginx** (routing, статика, rate-limit; **TLS/HSTS — требование прода**, в dev-стенде работает на HTTP, см. [architecture §9](architecture.md#9-инфраструктура)) |

## Монорепозиторий (рекомендуется)

Все внутренние проекты живут в одном репозитории (pnpm workspaces; turborepo — опционально):

```
mp-v2/
├── apps/
│   └── web/                  # Next.js (FSD)
├── services/                 # 8 бэкенд-проектов NestJS (FSD + Prisma)
│   ├── gateway/              # api-gateway: JWT, роли, маршрутизация, trace-id
│   ├── identity/             # саги Keycloak, связки user↔patient/doctor, db_identity
│   ├── catalog/              # врачи, специализации, расписания, db_catalog
│   ├── patient/              # карточки пациентов, db_patients
│   ├── file/                 # реестр объектов MinIO, db_files
│   ├── scheduling/           # слоты, записи, результаты приёма, db_schedule
│   ├── report/               # CQRS read-model, db_report
│   └── notification/         # email-уведомления (SMTP)
├── packages/
│   ├── contracts/            # OpenAPI-контракты + схемы событий (Zod) + генерируемые TS-типы
│   ├── service-kit/          # переиспользуемая инфраструктура: pino, trace-id, health, outbox/inbox, RabbitMQ, JWKS
│   ├── storage/              # presigned-клиент MinIO/S3 (задача 0.5)
│   ├── mp-ui-kit/            # дизайн-система: компоненты Mp* (Material UI), тема и токены, Storybook
│   ├── eslint-config-fsd/    # общие правила границ FSD для всех проектов
│   └── tsconfig/             # общие tsconfig-пресеты
├── scripts/                  # generate-service.mjs + service-template — генератор каркаса сервиса
├── docs/                     # документация проекта (этот каталог: new-project/)
└── infra/                    # docker-compose, nginx, манифест Keycloak, init-скрипты Postgres/MinIO, filebeat
```

Документация проекта живёт в [`docs/new-project/`](README.md) этого репозитория — рядом с кодом, под версионированием; индекс документации существующей (v1) системы — в [`../../../docs/README.md`](../../../docs/README.md).

Зачем монорепо: атомарные изменения контрактов, единый пресет правил FSD, один CI, отсутствие рассинхрона версий. Альтернатива (отдельный репозиторий на сервис) допустима, но требует отдельного репо для `contracts` и синхронизации версий.

## Ключевые отличия от текущей системы

1. **Микросервисы с событийной моделью** вместо одного Spring-монолита: независимые релизы, изоляция отказов, CQRS для отчётов.
2. **Keycloak** вместо собственной генерации JWT и bcrypt-хранилища — роли реально работают, SSO и backchannel logout из коробки.
3. **NestJS + TypeScript strict + Prisma** — сквозная типобезопасность вместо ручных DTO и опечаток вроде `patientiddlename`.
4. **Feature-Sliced Design** во всех проектах — слои, слайсы, запрет кросс-импортов, enforced на уровне ESLint.
5. **Данные как события** — RabbitMQ + outbox: уведомления, аудит и отчёты не замедляют запись к врачу.
6. **Качество кода как ворота CI** — ESLint/Prettier/Typecheck/тесты блокируют мердж.
7. **Инфраструктура как код** — compose с томами, миграциями, импортом реалма Keycloak и созданием бакетов MinIO.
8. **Дизайн-система Material UI** — вместо самодельного UI-кита: тема и токены бренда, готовые доступные компоненты, обёртки в `shared/ui` (единая точка стилизации, импорт `@mui/*` только оттуда).
9. **BFF + SSR** — браузер не ходит в API напрямую: сервер `web` агрегирует вызовы (`/api/bff/*`) и отдаёт страницы отрендеренными; токен не покидает сервер.
10. **MVC + Hexagonal внутри сервисов** — ядро (домен, use-case) не знает про HTTP/БД/брокер, тестируется без инфраструктуры; зависимости направлены внутрь и проверяются линтом.
